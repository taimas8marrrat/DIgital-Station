# Цифровая станция Актогай

Прототип системы поддержки решений для станции Актогай (КТЖ): цифровой двойник станции, ИИ-планирование (OR-Tools CP-SAT), индекс эффективности 0–100, схема станции в пиксель-арте, диаграмма Ганта, конфликты → решения, перемотка, отчёт PDF/CSV. Интерфейс на русском и казахском.

**Система предлагает — дежурный по станции подтверждает.** Доступа к СЦБ нет. Все данные — модель (mock).

Логины: `dsp / dsp` — диспетчер, `admin / admin` — администратор (может менять веса индекса).

---

## Способ 1. Быстрый запуск без Docker (нужен только Python)

Интерфейс уже собран (папка `frontend/dist`), Node.js не нужен.

1. Установите **Python 3.12** с сайта python.org. В установщике поставьте галочку **«Add python.exe to PATH»**.
2. Откройте папку проекта в VS Code или PyCharm.
3. Откройте терминал (VS Code: меню **Terminal → New Terminal**) и выполните по очереди:
   ```
   cd backend
   python -m pip install -r requirements.txt
   cd ..
   python run.py
   ```
4. Откройте в браузере **http://localhost:8000**. Документация API: **http://localhost:8000/docs**.
5. Остановить: в терминале нажмите `Ctrl + C`.

В этом режиме база — SQLite, шина — встроенная.

## Способ 2. Полный запуск через Docker (микросервисы, Redis, TimescaleDB)

1. Установите **Docker Desktop** для Windows и запустите его (дождитесь зелёного статуса).
2. В терминале в папке проекта:
   ```
   copy .env.example .env
   docker compose up --build
   ```
3. Откройте **http://localhost:8000**. Остановить: `Ctrl + C`, затем `docker compose down`.

Сервисы: `simulator` → `ingest` (порт 8001) → Redis Streams → `core` (порт 8000) → TimescaleDB.

## Что нового в версии 2.3
- Интерфейс v2.3: длинная панорама, поезда едут по рельсам, смена дня и ночи, люди на станции (ДСП, осмотрщики ПТО, бригады, пассажиры), диаграмма движения 60 кадров/с.
- Умная скорость «Авто»: спокойно ×288, при сбое замедление до ×10.
- Крупные нештатные ситуации: сход вагона, ураганный ветер, отказ СЦБ горловины (`POST /api/scenario/disaster`).
- Автопилот (демо-режим модели): рекомендованный план применяется через 2,5 с (`POST /api/planner/autopilot`). В эксплуатации решение остаётся за ДСП.
- Решатель CP-SAT работает в отдельном процессе: если OR-Tools аварийно завершится, сервер не падает и временно переходит на эвристику.
- Демо-режим по умолчанию: старт 11:20, случайные сбои выключены (см. `.env.example`).

## Сравнение «вручную / цифровая станция»
```
cd backend
python ../scripts/compare_day.py --scenarios 10
```
Результат сохраняется в `scripts/compare_result.json`. Ручная работа моделируется так: очередь по времени прибытия, первый свободный путь, реакция 5 минут, пересчёт раз в 5 минут.

## Как показать демо (3 минуты)
1. Войти `dsp / dsp`. Показать схему, индекс, Гант.
2. Кнопка **«Нештатная ситуация»** → «Закрыть путь» 4 на 60 мин. Справа появится проблема, правило и 3 варианта решения с временем расчёта.
3. Навести курсор на вариант — на Ганте видно новый план. Нажать **«Принять»**.
4. Кнопка **«Нагрузка ×10»** — 10 нештатных ситуаций сразу, план пересчитывается за доли секунды.
5. Блок «Вручную и цифровая станция» — сравнение на одном горизонте.
6. **«−15 мин»** — перемотка истории. **«Отчёт»** → PDF или CSV.
7. Переключить **RU / KZ**.

## Что нового в версии 3
- **«Демо» в один клик** (группа «Действия»): сценарий из 5 шагов с субтитрами RU/KZ. Пробел — пауза, → — дальше, Esc — стоп.
- **«Эффект за год»**: поездо-часы и потери в ₸ по результатам пакетного прогона; ставка задаётся на экране.
- **«Почему этот вариант»** в карточке решения.
- **Неопределённость прибытия**: «11:34 ±3 мин» и полоса разброса на диаграмме; план строится с запасом.
- **Тренажёр ДСП** («Настройки»): 3 ситуации, выбор без подсказки, оценка.
- **Рост потока ×1,6** в живой модели («Настройки → Поток поездов»).
- **Отчёт для руководства** — одна страница PDF («Отчёт → PDF для руководства»).
- CI (GitHub Actions): тесты, проверка запуска сервиса и сборка интерфейса при каждом push.

## Что нового в версии 2.4
- **Два режима вида:** «Диспетчерский» (строгая схема) и «Наглядный» (пиксельная станция с людьми и сменой дня и ночи). Переключатель — в группе «Вид» на верхней панели.
- Стрелочные улицы под постоянным углом, маршруты подсвечиваются, хвостовой сигнал, этапы обработки поезда: прибытие → осмотр ПТО → смена локомотива → смена бригады → опробование тормозов → отправление.
- Крупные нештатные ситуации (сход вагона, ураганный ветер, отказ СЦБ) и **автопилот — демо-режим модели**: система сама применяет рекомендованный план через 2,5 с. В эксплуатации это подсказка с таймером, решение за ДСП.
- Отраслевые показатели: выполнение графика, задержки по вине станции (поездо-часы), простой транзитного вагона, потери в тенге (условная ставка задаётся в «Настройках»).
- Решатель OR-Tools работает в отдельном процессе: если он аварийно завершится, сервер не упадёт, а продолжит на эвристике и перейдёт на 1 поток.

## Пересборка интерфейса сервиса (только если меняли код интерфейса)
В PowerShell, в папке `frontend`:
```
npm install
$env:VITE_SOURCE="server"; npx vite build
```

## Параметры без перекомпиляции
- `backend/config/index.json` — веса и пороги индекса (или окно «Настройки» под `admin`).
- `backend/config/planner.json` — лимит времени решателя, приоритеты, автопринятие.
- `.env` — пароли, скорость симуляции (`SIM_SPEED`), частота потока (`SIM_TICK_HZ`).

## Служебное
- `GET /health` — состояние, `GET /metrics` — метрики Prometheus, логи — JSON в консоли.
- Тесты планировщика: `cd backend` → `python -m pip install pytest` → `python -m pytest -q`.
- Новое расписание: `python backend/data/generate_timetable.py --seed 7`.
- Сборка интерфейса после правок (нужен Node.js 20), PowerShell: `cd frontend` → `npm install` → `$env:VITE_SOURCE="server"; npx vite build`. Без переменной собирается сайт одним HTML-файлом (браузерная версия без сервера).

## Структура
```
backend/app/        core: двойник, планировщик, индекс, API, отчёты
backend/simulator/  симулятор потока событий
backend/data/       станция, ресурсы, расписание (mock)
backend/config/     формула индекса и параметры планировщика
frontend/src/       интерфейс React + TypeScript
docs/               архитектура и спецификация данных
```
